# NEXUSA — VorPy Export and Scope Architecture Audit

**Date:** 2026-10-19  
**Status:** design/audit only; no calculation, solver, export, formula, or existing output was changed.

## Executive result

VorPy already has the beginnings of the requested three-scope model:

- `System` owns the molecular table, source metadata, groups/interfaces, and the archive root.
- `Group` owns ordinary network outputs.
- `Interface` owns a selected physical A/B view, contact tables, interface meshes, and interface logs.
- `ExportScope` and `NetworkView` prevent a materialized interface export from silently widening to unrelated source surfaces.
- `load_network()` is a self-contained, no-rebuild reload path.

The layout and preset vocabulary are not yet a clean architecture. The main findings are:

1. The current CLI has two different meanings for `tiny`: the `tiny` command maps to the internal `micro` preset, while the internal `tiny` preset is separate. Both are metadata-only and produce no edge visualization.
2. The CLI `small` path maps to the internal `small` preset. It writes a surface mesh and canonical interface logs, but not the classic interface scheme log requested for the proposed “small” tier.
3. `-e small add surfs` and `-e large no shell` are not implemented as modifiers. The parser keeps the whole token block but `argv_export()` dispatches only the first token. A separate `-e add ...` is an unknown export.
4. Current output code writes compatibility aliases (`network_info.txt` beside `interface_info.txt`) and can write several overlapping log forms. The proposed hierarchy should retain aliases only as compatibility derivatives.
5. The archive format is materially useful: it stores source generators, topology, provenance, solvent policy, analysis caches, representation links, typed-result snapshots, and dependency validation. It does not implement a general incremental solve plan for an unsolved Group C.
6. Exact output size is dominated by meshes, repeated atom-cell meshes, and legacy logs. A preserved interface artifact was 14 files / 51,137,151 bytes, of which `logs.csv` was 47,023,524 bytes. The same artifact’s physical files without that legacy canonical log were 12 files / 3,850,696 bytes.

## 1. Current directory and ownership model

### Current shape

The normal layout is effectively:

```text
<run-root>/
  system_info.txt
  <system>.pdb                         # when requested
  set_atoms.pml                        # when requested
  <system>.vpy                         # most named presets, unless disabled
  <system>.vpy.timing.json              # opt-in diagnostic/profile sidecar
  <net_type>_verts.txt                  # legacy/debug, often moved under a group
  <group-name>/                          # ordinary Group exports
    network_info.txt
    <net_type>_logs.csv
    surfs.off / edges.off / verts.off
    shell_*.off, atoms/, layers/ ...
  <group-a>_<group-b>_interface/
    interface_info.txt
    network_info.txt                     # compatibility copy
    interface_surfs.off / interface_edges.off / interface_verts.off
    interface_surfaces.csv / ...
    group_a_atoms.pdb / group_b_atoms.pdb / surr_*.pdb
    <net_type>_logs.csv, logs.csv, logs.compact.csv, logs.provenance.json
  .vorpy/checkpoints/<name>.geometry.vpy  # internal solved-geometry checkpoint
  apollonius/, aw_alpha/, visualization/  # optional derivatives
```

This layout is readable, but it mixes source/system files, scope outputs, compatibility files, and diagnostics at one level. It also makes the archive policy look like a file export rather than a shared scientific checkpoint.

### Proposed shape

```text
<run-root>/
  <system_name>_checkpoint.vpy             # one shared checkpoint, if selected
  manifest.json                            # scope/preset/schema map
  system/
    system_info.txt
    source.pdb                              # one copy only when requested
    set_atoms.pml
    network/                                # only when a system network was requested
      network_info.txt
      <net_type>_logs.csv
      surfs.off / edges.off / verts.off ...
  groups/
    <stable-group-id>/
      group_info.txt
      group_atoms.pdb
      <primary geometry and analysis files>
  interfaces/
    <stable-interface-id>/
      interface_info.txt
      group_a_atoms.pdb / group_b_atoms.pdb
      interface_edges.off                  # tiny visual baseline
      <direct physical meshes/tables/logs>
      derived/                              # dual, alpha, water, contacts, diagnostics
  diagnostics/
    timing.json
    legacy/
    analysis/
```

`network_info.txt` should remain readable as a compatibility alias, but `group_info.txt` and `interface_info.txt` should be the canonical names in a future layout. A group or interface directory must never receive a duplicate full-system network merely because that scope was selected.

### Additive/subtractive syntax finding

`-e small and shell` works because `and` separates two export commands. `add` and `no` are not general modifiers:

- `-e small add surfs` is retained as one token block and only `small` is dispatched; `add surfs` is ignored.
- `-e large no shell` similarly dispatches `large` and does not remove shell products.
- a separately parsed `-e add ...` is unknown.
- `-e only ...` is a separate, working replacement-style mechanism.

This must be documented as unsupported until PRISM defines a grammar and tests it. Presets must remain output-only; they must not alter calculation scope.

## 4. Proposed five export tiers

These are design assignments, not implemented behavior. A preset changes files written; it must not change the requested geometry or analysis profile.

Legend: `P` = proposed; `C` = compatibility output; `R` = requires an already available result; `O` = optional/explicit.

| Tier | Proposed system outputs | Required analysis/geometry | Value and cost |

## 5. Checkpoint/archive gap analysis

### What already works

`network_archive.py` is a versioned ZIP document (`FORMAT_VERSION = 3`) containing JSON metadata, tables, and NumPy arrays. It records or validates:

- molecular atom/residue/chain identity and original source path/hash when available;
- generator system indices, stable generator IDs, boundary generators, solvent mode and solvent membership;
- network topology and incidence, group membership, source-network identity, and network scope;
- interface geometry analysis, alpha/dual/representation caches and links;
- typed Results snapshots, dependencies, geometry lineage, and archive cache state;
- archive timing/profile data when requested.

`load_network()` explicitly never builds or analyzes geometry. `group_from_network()` can create a new selection sharing an existing solved network, but it rejects selected cells that are not complete. Interface archive recovery uses an existing source network and source-view selection; it does not build a second network.

### What is missing for the requested shared checkpoint

The current archive is a solved-state checkpoint, not a general incremental construction database. It lacks a proven API for:

1. loading a checkpoint with an unsolved Group C definition;
2. validating that C’s generator universe and competitor policy are compatible with the stored source context;
3. constructing only missing C cells while reusing unaffected A/B vertices, edges, surfaces, and incidence;
4. merging new topology without changing stable identities or invalidating dependent interface/analysis caches;
5. representing a partial build plan separately from a complete-network archive validation contract;
6. atomically updating one shared checkpoint while keeping a previous scientific state recoverable.

The archive can preserve partial/incomplete rows and explicit unavailable analysis state, but that is not evidence that an incremental solver merge is implemented. Do not advertise “continue Group C” until FORGE defines dependency closure and ATLAS defines cache invalidation.

### Expected checkpoint growth

The bounded EDTA archive is about 2.59 MB compressed for 612 source/context generators and a solved network. A preserved 1BNA full-system geometry checkpoint is about 514 MB. The large spread is consistent with dense interface/full-network topology and repeated table/array content; it is not a reliable universal estimate. The archive should expose member counts, compressed/uncompressed bytes, and object/table counts before the default policy is fixed.

| Axis | Current control | Meaning |
|---|---|---|
| calculation target | `-c system|groups|interface`, `-g`, `-i` | what geometry is constructed or viewed |
| solver/method | `-s nt aw|pow|prm` and settings | geometry definition and numerical settings |
| solvent policy | `--solvent-mode MOLECULE_ONLY|SOLVENT_CONTEXT|FULL_SOLVENT` | competitor universe and cell-dependent behavior |
| analysis depth | `--profile geometry|interface|analysis|full` | curvature, water, and optional analysis work |
| export preset/components | `-e ...` | files written from available results |
| archive/cache profile | `--save-network`, `--profile-cache-export`, timing flags | persistence and performance evidence |

Current timing instrumentation already separates input/loading, geometry-network timing, analysis, export, and archive save in the optional timing report. Export sub-stages include scope selection, mesh generation, contact PDBs, info, legacy logs, physical tables, dual, vertices, edges, and surfaces. “Meshing” is currently nested under export stages rather than a first-class top-level phase. The next performance report should normalize:

```text
load | solve/geometry | analysis | meshing | export serialization | archive save
```

without double-counting mesh work or archive time.

No implicit full-system solve should be introduced by curvature, visualization, or export requests. A cache-only reload must be able to export derivatives without `Network.build()`.

## 7. Scientific status and completeness rules

- Direct physical A/B facets are the only primary interface area.
- Supporting/internal facets are evidence and optional visualization, not direct contact area.
- No-contact A/B is a valid empty interface with empty meshes and `NOT_CALCULATED`/empty status, not a fabricated geometry failure.
- Incomplete source views may export only a locally validated selected subset. Unresolved surfaces, unsupported edges/vertices, unbounded features, and missing coverage remain visible.
- Group atom-cell exports skip incomplete cells. Classic logs retain `Complete Cell? = False`; unavailable curvature remains blank/unavailable.
- FULL_SOLVENT is a competitor/cell policy, not a requirement for every direct interface measurement. Water-cell-dependent metrics retain strict complete-solvent gates.
- AW dual and center-connected alpha representations are derived visualizations. They must not be labeled physical curved AW surfaces.
- Reconstructed dual-contact triangulation of complete DNA-side and ligand-side patches with natural outer boundaries remains deferred. It is not assigned to any tier in this cycle.

## 9. Migration proposal

Migration should be additive and reader-first:

1. Emit a versioned root `manifest.json` mapping old paths to new scope IDs and recording the preset, analysis profile, solvent mode, method, and archive identity.
2. Keep current paths and `network_info.txt` readable for one compatibility period; do not overwrite or delete existing outputs.
3. Make `system/`, `groups/<stable-id>/`, and `interfaces/<stable-id>/` canonical for new writes.
4. Keep one shared `<system_name>_checkpoint.vpy`; stop creating per-interface full-network archives by default. Existing `.vorpy/checkpoints/*.geometry.vpy` remains readable and can be migrated by explicit copy/re-save after validation.
5. Move advanced outputs below scope-local `derived/` or `diagnostics/`, with manifests that identify the canonical source cache.
6. Make canonical Results + compact provenance the preferred typed output; keep the large legacy canonical CSV as explicit compatibility output after ATLAS/VECTOR reader review.
7. Treat `aw_verts.txt`, `_net.csv`, old info aliases, and per-feature meshes as explicit legacy/debug exports rather than hidden default products.

No migration should change geometry, completeness flags, interface identity, method formulas, or solvent competitors.

## 11. Recommended non-overlapping implementation order

1. **NEXUSA:** freeze the scope manifest, tier contract, status vocabulary, and migration aliases. No solver edits.
2. **PRISM:** own calculation/export planning, tier selection, and additive/subtractive parser semantics in command modules and CLI regressions. Do not edit writer internals.
3. **VECTOR:** own output layout, mesh/table/log serialization, compatibility aliases, and stage timing labels. Do not change geometry or analysis.
4. **ATLAS:** own typed Results, compact provenance, archive dependency snapshots, and checkpoint invalidation semantics. Coordinate archive schema before implementation.
5. **FORGE:** own source-network/interface scope, completeness, solvent participation, and any incremental geometry API. Keep primary geometry independent of optional dual/contact analysis.
6. **GAUSS:** own analysis profile definitions, certification/status rules, and acceptance comparisons for area, contacts, curvature, and topology.
7. **NEXUSA:** run bounded synthetic/reload/export equivalence tests, then request user-operated molecular pilots. Only NEXUSA updates root `results.txt`.

This order prevents PRISM, VECTOR, ATLAS, and FORGE from changing shared archive/export contracts concurrently.

## Audit conclusion

The recommended minimal preset is **proposed `small`**: system/interface info, direct edge and surface visualization, contact atoms, the classic scheme log for compatibility, compact typed Results plus one provenance sidecar, and no unrelated group/full-system network output. The current implementation is closest to this behavior but does not yet satisfy the edge visualization, classic interface log, additive/subtractive syntax, or single-checkpoint policy consistently.

Skipped: no new tests or molecular solves were run because this was explicitly an audit-only task. Risk remains around the unresolved archive default, legacy-log compatibility, and the missing incremental Group-C checkpoint API.
