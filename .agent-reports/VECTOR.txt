## 2026-10-20 Agent 3 curvature availability audit

The EDTA source-edit freeze remains uncleared. No executable source or test
file was changed in this pass; only this report was updated. The audit was
bounded and used no molecular solve or production geometry.

Confirmed data-path findings:

- The typed Results model already has the required distinction. `Quantity`
  rejects a value for `UNRESOLVED`, `NOT_CALCULATED`, or `NOT_SUPPORTED`, and
  carries units, method, scope, and coverage counts. The typed interface
  curvature records preserve nullable values and statuses.
- The legacy Group path does not carry that distinction. `Group.__init__`,
  `group/sort.py`, and `network/analyze.py` initialize integrated H²/K and
  component reductions to `0.0`. `Network.build(calculate_curvature=False)`
  also writes zero curvature arrays for geometry-only builds. POW/PRM flat
  surfaces legitimately have numerical zero only when the flat geometry
  branch is the declared calculation; geometry-only builds must not reuse the
  same representation for “not calculated”.
- `interface/export.py::summarize_direct_interface_orientation` still uses
  `float(surf.get(..., 0.0) or 0.0)` for H, H², and K, and its summary starts
  those totals at zero. Missing direct-interface curvature is therefore
  reported as a numerical zero. The same file’s group/water summary path
  coerces missing group curvature to zero and derives `2*q` energy.
- `interface/water.py::summarize_water_group` has the same coercion and derives
  surface energy from H² without a calculation-status guard.
- The legacy `output/logs.py` writer defaults group component fields and
  representative energy to zero or `2 * int_mean_curv_sq`; its newer mapping
  writer leaves individual missing values blank but still has the same energy
  fallback when `surf_energy` is absent. Existing group-info status handling
  from GAUSS is better, but does not repair these CSV/log paths.
- `calculations/surface_energy.py::sum_surface_energy_geometry` converts
  absent geometry keys to zero. A bounded call with `[{"Area": 2.0}]`
  returned zero H²/K and `calc_helfrich_energy` then returned a finite area-only
  energy. This is the clearest confirmed downstream scientific defect.
  Direct `calc_helfrich_energy` on explicit `None` fails with `TypeError`,
  which is safer; the preceding aggregation can hide the missing state.
- `calc_surface_energy_geometry_from_curvatures` converts non-finite H/K to
  zero. This is only valid if non-finite means a measured zero, not when the
  producer omitted curvature; the API currently has no status argument to
  distinguish those cases.

Ownership/conflict boundaries:

- `group/export.py` and `interface/export.py` already contain concurrent GAUSS/
  VECTOR changes. I did not overwrite them. GAUSS’s handoff specifically
  identifies the interface missing-zero path as coordinated follow-up.
- A complete fix needs a producer-level availability/status contract in the
  network/group layer, then the legacy logs/interface writers and surface
  energy reducers must consume it. It should preserve numeric zero only for a
  completed calculation whose value is zero, and emit blank/status text for
  `NOT_CALCULATED`, `NOT_SUPPORTED`, and `UNRESOLVED`/incomplete boundaries.
