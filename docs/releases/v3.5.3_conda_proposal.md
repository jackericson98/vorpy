# Proposed conda-forge update for VorPy 3.5.3

No feedstock recipe is present in this repository. The current conda-forge
query exposes `vorpy3` 3.5.0, while the candidate metadata is 3.5.3.

Proposed update fields:

```yaml
package:
  name: vorpy3
  version: 3.5.3
source:
  url: https://github.com/jackericson98/vorpy/archive/refs/tags/v3.5.3.tar.gz
  sha256: <compute from the final tagged upstream source archive>
requirements:
  host:
    - python >=3.10
    - pip
    - setuptools >=77
    - wheel
  run:
    - python >=3.10
    - numpy >=2.0
    - scipy >=1.10
    - matplotlib-base >=3.9
    - pandas >=1.2
    - numba
    - shapely >=2.0
    - pillow
test:
  commands:
    - python -c "import vorpy; assert vorpy.__version__ == '3.5.3'"
    - vorpy --help
    - python -m vorpy --help
    - python -m vorpy "$PREFIX/lib/python{{ environ['PY_VER'] }}/site-packages/vorpy/data/HO_cube.pdb" -s nt pow and mv 5 --boundary shell -e none
  requires:
    - pip
    - pytest
about:
  license: MIT
  license_family: MIT
  license_file: LICENSE
extra:
  recipe-maintainers:
    - jackericson
```

The source URL and SHA-256 cannot be finalized until the reviewed 3.5.3
source-only commit is tagged or an equivalent upstream archive is generated.
GUI dependencies should remain optional rather than entering the core noarch
runtime set. GUDHI is likewise optional. Feedstock submission is not part of
this round.
